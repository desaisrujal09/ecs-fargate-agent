This Lambda function powers an AutoSRE Slack bot for an ECS/Fargate application. It supports both automated incident alerts and interactive troubleshooting through Slack. Receives two event types: Slack events through API Gateway and ECS failure events (such as an EventBridge-triggered task failure).
Parses and validates Slack requests: It handles JSON, Base64 payloads, Slack URL-verification challenges, and ignores Slack retry events and bot-generated messages to prevent duplicate replies or loops.

Responds to ECS failures: When an ECS task failure triggers the Lambda, it retrieves recent messages from the latest CloudWatch log stream in /ecs/fargate-test-app.
Uses Amazon Bedrock Nova Lite: It sends those logs to the Nova Lite model, asking it to produce a short root-cause analysis and prevention recommendation.
Posts incident alerts to Slack: The AI-generated failure analysis is sent directly to a configured Slack channel using the Slack Web API.
Supports Slack chat queries: When an engineer mentions or messages the bot, it fetches current application logs and asks Bedrock to answer as a senior SRE teammate.
Maintains thread memory: It saves user questions and bot responses in DynamoDB, keyed by Slack thread timestamp, with a 24-hour TTL. This lets the bot retain recent context within a troubleshooting thread.
Keeps responses scoped: The prompt tells the model to handle small talk naturally, answer ECS-app-related technical questions using logs, and refuse unrelated questions with a fixed response.
Replies in the same Slack thread: Bot answers are posted with thread_ts, keeping troubleshooting conversations organized.

In short, it is an AI-assisted incident-response workflow: ECS failure or Slack question → fetch CloudWatch logs → analyze with Bedrock → notify or answer in Slack → save the conversation in DynamoDB.
